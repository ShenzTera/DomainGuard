# Fix Plan: Resolve Login Error on Cloudflare Pages & GitHub Hosting

## 1. Problem Analysis
When hosting DomainGuard via GitHub on **Cloudflare Pages**:
1. **Missing Backend Server on Static Edge**: Cloudflare Pages by default serves only the built static frontend (`dist/` generated by `vite build`). The Express server (`server.ts`) does not run on Cloudflare Pages.
2. **Login Network Failures (`/api/auth/*`)**: When attempting to log in, register, or authenticate via Google, the frontend sends requests to `/api/auth/login`, `/api/auth/register`, etc. Because no Node.js backend is active, Cloudflare responds with `404 Not Found` or an HTML SPA error page, which causes JSON parsing to fail and displays an authentication error.
3. **SPA Routing**: Directly navigating or refreshing pages on Cloudflare Pages can lead to 404 errors without a `_routes.json` or `_redirects` configuration.

---

## 2. Proposed Architecture & Solution

### Phase 1: Resilient Client-Side Hybrid Auth Fallback
- Update `src/context/AuthContext.tsx` with smart hybrid fallback logic:
  - Attempt `/api/auth/login`, `/api/auth/register`, and `/api/auth/me`.
  - If the server responds with 404, network error, or invalid JSON (indicating a static edge host like Cloudflare Pages or GitHub Pages), automatically switch to the resilient client-side authentication engine.
  - Support instant login with the pre-seeded accounts (`admin@domainguard.io` / `Admin123!` and `demo@domainguard.io` / `Demo123!`), self-registration, and Google login stored securely in browser `localStorage`.
  - Provide direct client-side Supabase authentication if Supabase keys are configured.

### Phase 2: Native Cloudflare Pages Functions & Configuration
- Create `functions/api/[[path]].ts` using Cloudflare Pages Functions (edge runtime):
  - Handle `/api/auth/*` (login, register, session validation, password reset) directly at the Cloudflare edge.
  - Proxy WHOIS and RDAP lookups to bypass browser CORS on Cloudflare Pages.
  - Handle Telegram alerts and test pings serverlessly via Cloudflare Worker runtime.
- Add `public/_redirects` and `public/_routes.json`:
  - Ensure client-side SPA routing works seamlessly without 404s on browser reloads.

### Phase 3: Domain Service & Notification Graceful Fallback
- Update `src/lib/domainService.ts`:
  - When running in static/Pages mode without an Express backend, perform direct ICANN RDAP DNS queries and direct Telegram Bot API requests via `fetch` from the browser/edge worker.
  - Ensure all core domain tracking, automated alert countdowns, and CSV imports function smoothly on Cloudflare.

### Phase 4: Production Server Hardening for Node.js Hosts
- Update `server.ts` to respect dynamic host environment variables (`process.env.PORT || 3000`), allowing users to optionally run on full-stack hosts (Render, Railway, Fly.io, VPS) without port conflicts.
